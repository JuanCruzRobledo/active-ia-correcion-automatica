## Project Overview

**Active-IA** es una plataforma de corrección automática de trabajos prácticos con IA para la TUD.

### Módulos Principales

| Módulo | Descripción |
|--------|-------------|
| Autenticación | Login JWT, cambio de contraseña |
| Usuarios | CRUD usuarios, asignación de roles |
| Materias | CRUD materias, asignación de coordinadores |
| Comisiones | CRUD comisiones, asignación de tutores |
| Rúbricas | Crear manual/IA, duplicar, 7 tipos |
| Entregas | Carga individual/masiva, consolidación código |
| Corrección | Individual/lote, re-corrección, integración Gemini |
| Edición | Modificar nota, criterios, feedback |
| Documentos | PDFs de devolución, exportación Excel |
| Perfil | Datos personales, API Key Gemini |

### Modelo de Datos

```
Usuario ─┬─> CoordinadorMateria ──> Materia
         └─> ComisionTutor ──> Comision ──> Materia
                                   │
                                   ├── Entrega ──> Correccion
                                   │      └── EntregaHistorial
                                   └── Rubrica
```

### Roles

| Rol | Permisos |
|-----|----------|
| Admin | Gestión total de la plataforma |
| Coordinador | Gestiona rúbricas y comisiones de sus materias |
| Tutor | Corrige entregas de sus comisiones |

## Critical Rules

### ALWAYS
- Seguir Clean Architecture en backend (Router → Service → Repository)
- Usar TypeScript strict en frontend
- Validar permisos en cada endpoint
- Encriptar API Keys con AES-128-CBC (Fernet)
- Usar JSONB para criterios de rúbricas y correcciones
- Máximo 500 LOC por archivo
- Soft delete para auditoría

### NEVER
- Lógica de negocio en Routers
- Acceso directo a BD desde Services
- Almacenar API Keys en texto plano
- Exponer información sensible en logs
- Commits sin mensaje descriptivo
- Push directo a main/master

## Decision Trees

### ¿Dónde colocar código nuevo?

| Situación | Ubicación |
|-----------|-----------|
| Nuevo endpoint API | `backend/app/routers/` |
| Lógica de negocio | `backend/app/services/` |
| Acceso a BD | `backend/app/repositories/` |
| Modelo SQLAlchemy | `backend/app/models/` |
| Schema Pydantic | `backend/app/schemas/` |
| Componente React | `frontend/src/features/{modulo}/components/` |
| Hook compartido | `frontend/src/shared/hooks/` |
| Servicio API | `frontend/src/shared/services/` |

### ¿Cómo manejar errores?

| Tipo | Acción |
|------|--------|
| Validación de entrada | HTTPException 400 + mensaje específico |
| No encontrado | HTTPException 404 |
| Sin permisos | HTTPException 403 |
| Error de IA | HTTPException 502 + retry |
| Error interno | HTTPException 500 + log detallado |

## Commit Guidelines

Seguir Conventional Commits:

```
<type>(<scope>): <description>

[optional body]
```

### Types
- `feat`: Nueva funcionalidad
- `fix`: Corrección de bug
- `refactor`: Refactorización sin cambio funcional
- `docs`: Documentación
- `test`: Tests
- `chore`: Tareas de mantenimiento

### Scopes
- `auth`: Autenticación
- `users`: Usuarios
- `materias`: Materias
- `comisiones`: Comisiones
- `rubricas`: Rúbricas
- `entregas`: Entregas
- `correcciones`: Correcciones
- `docs`: Documentos PDF/Excel
- `api`: Backend general
- `ui`: Frontend general
